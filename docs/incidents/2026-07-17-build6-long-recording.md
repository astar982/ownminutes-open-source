# 2026-07-17 Build 6 长录音与实时转写事故

## 结论

- TestFlight `1.0.0 (6)` 已判定 **No-Go**，不得用于 App Store 正式审核。
- 用户 09:06 开始的长会议并未丢失。服务端已收到完整正式音频并完成最终处理。
- 用户 10:14 开始的第二场录音没有任何请求到达 Caddy、App、对象存储或数据库；原音频只能先从该 iPhone 的 `Documents/ExpoAudio` 恢复。不要卸载 App、清除数据或退出账号。
- 事故包含两个独立问题：实时草稿生产速度高于服务端消费速度，以及客户端在实时请求失败后永久取消队列。正式录音虽然独立保存在本机，但异常恢复、索引持久化、跨会议状态隔离和后台续传的边界仍不够可靠。

- 正式音频：`41,196,872` bytes，权威媒体时长 `21:27.274`。
- 上传：10 个正式音频分片全部 HTTP 200；09:43:40 完成 commit。

## 根因

1. Build 6 每 3 秒生成一个实时 PCM 请求，但当时成功请求耗时约 3.7–5.5 秒；串行队列必然不断积压。
2. 队列达到上限后丢弃实时草稿；最终传输错误又取消整个实时队列，后续即使网络恢复也不会继续实时转写。
3. 正式录音与实时草稿是两条链路。正式录音仍写入本机，但旧实现存在停止顺序、文件移动后索引未提交、iOS media services reset、孤立文件自动匹配和第二场会议状态串写等恢复风险。
4. 后台续传锁冲突会丢弃显式重试的 `force / onlyMeetingId / showActiveResult`，并可能把旧会议进度或结果写到新会议页面。

## Build 7 修复边界

- 正式录音继续作为唯一耐久事实源；实时转写只作为可丢弃草稿，任何实时错误都不得停止正式录音。
- 实时分片从 3 秒调整为 10 秒，队列上限从 20 调整为 6；失败后使用有界退避并从正确 sequence 继续，而不是永久取消会话。
- 结束会议时先冻结原始 URI、停止正式 recorder，再停止次要 AudioStream；本地恢复索引落盘后立即向用户确认本机已保存，云端上传和最终处理转入后台。
- 不再在恢复索引提交前移动正式录音文件，消除“文件已移动但索引仍指向旧路径”的崩溃窗口。
- 同时扫描 Expo Documents 根目录和原生 `Documents/ExpoAudio`；只有唯一候选、唯一 orphan、候选仍标记 active 且原文件缺失/过小时才允许自动关联。其他孤立音频全部隔离为仅本地恢复，禁止猜测会议后自动上传。
- `mediaServicesDidReset`、本地文件缺失/停止增长、启动/停止超时均进入可恢复状态；连续两次文件健康探针异常才执行单次安全停止。
- 新会议不再删除旧会议本地音频；异常录音可保留恢复卡片，同时允许创建第二场会议。
- 后台同步保留显式重试参数、录音期间不唤醒普通上传、按 session generation 隔离退出/换账号后的旧任务，并只允许匹配当前 meeting ID 的任务更新当前页面。

## 已完成的工程验证

- Web 与移动 TypeScript 通过。
- ESLint `--max-warnings=0` 通过。
- 录音存储、恢复索引、watchdog、media reset、实时队列、pending sync、三语/UI 门禁通过。
- 新增 30 分钟加速 soak：模拟 18,000 个 100ms PCM buffer、57.6 MB 正式录音、慢请求与超时、退避恢复、最多 6 个实时队列项；实时失败不停止正式录音，随后第二场 60 秒录音可正常开始并保存。
- 上述加速门禁只证明状态机和内存边界，不代替实体 iPhone 的真实 30/90 分钟验收。

## Build 7 发布门禁

Build 7 只有在以下条件全部满足后，才可从 TestFlight 候选升级为 App Store 审核候选：

1. 实体 iPhone TestFlight 5、30、90 分钟录音全部通过。
2. 30/90 分钟均能回放完整本地音频，上传完成，正式转写/纪要完成，会议历史可见。
3. 弱网、断网 60 秒后恢复、锁屏/后台、进程终止恢复、iOS 音频中断或 media reset 均不丢原音频。
4. 同一安装连续完成两场会议，第一场后台同步不得污染或阻塞第二场。
5. 完成私有 `recording:acceptance:evidence` 与 `ios:testflight:evidence`，且证据绑定 Build 7 和实际上传候选。

在完成这些真机证据前，可以生成本地 `1.0.0 (7)` 归档用于验证，但不得提交 App Review。
